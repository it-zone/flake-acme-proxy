# flake-acme-proxy

Nix flake packaging [`acme-proxy`](https://github.com/acme-proxy/acme-proxy), an ACME (RFC 8555) server written in Rust that can issue certificates from a local CA, relay requests to an upstream ACME CA, or delegate signing to a custom script.

This repository provides:

- the `acme-proxy` package
- an overlay that adds `pkgs.acme-proxy`
- a NixOS module for running `acme-proxy` as a systemd service

## Flake outputs

| Output | Description |
| --- | --- |
| `packages.<system>.acme-proxy` | `acme-proxy` package (`default` points here) |
| `overlays.default` | Adds `acme-proxy` to `pkgs` |
| `nixosModules.acme-proxy` | NixOS service module (`default` points here) |

Supported package systems: `x86_64-linux`, `aarch64-linux`, `x86_64-darwin`, `aarch64-darwin`.

## Usage

Add the flake as an input and import the NixOS module:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    acme-proxy.url = "github:it-zone/flake-acme-proxy";
  };

  outputs = { nixpkgs, acme-proxy, ... }: {
    nixosConfigurations.my-host = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        acme-proxy.nixosModules.default
        ({ ... }: {
          services.acme-proxy = {
            enable = true;

            # At least one profile is required.
            profiles.default = { };
          };
        })
      ];
    };
  };
}
```

The provided NixOS module imports the service definition and applies `overlays.default`, so `pkgs.acme-proxy` is available automatically.

You can also use the package directly:

```nix
# nix shell
nix shell github:it-zone/flake-acme-proxy
```

## NixOS module

Module: `services.acme-proxy`

The module renders `/etc/acme-proxy/config.toml` from Nix options, runs `acme-proxy` under a hardened systemd service, and persists state in `StateDirectory=acme-proxy` (service working directory: `services.acme-proxy.dataDir`, default `/var/lib/acme-proxy`).

At least one ACME profile must be declared via `services.acme-proxy.profiles.<name>` or `services.acme-proxy.settings.profiles.<name>`, otherwise evaluation/startup fails as enforced by the module/daemon.

### Top-level options

- `services.acme-proxy.enable` — enable the acme-proxy service.
- `services.acme-proxy.package` — package to run (defaults to `pkgs.acme-proxy`).
- `services.acme-proxy.dataDir` — state/working directory for the SQLite database, CA material, autogenerated TLS material, and relay keys (default: `/var/lib/acme-proxy`). Relative paths in configuration resolve against this directory.
- `services.acme-proxy.settings` — free-form TOML attrset written to `/etc/acme-proxy/config.toml` (merged with typed options below). See the [upstream example config](https://github.com/acme-proxy/acme-proxy/blob/master/config.toml.example) for the full schema.
- `services.acme-proxy.environmentFiles` — daemon-wide systemd `EnvironmentFile=` paths (read from host at activation, not stored in the Nix store). Loaded before per-profile environment files.
- `services.acme-proxy.openFirewall` — open the ACME listener TCP port parsed from `settings.server.bind_address`.
- `services.acme-proxy.openAdminFirewall` — open the admin UI TCP port parsed from `settings.admin.bind_address` (only effective when `settings.admin.enabled = true`).
- `services.acme-proxy.openMetricsFirewall` — open the Prometheus metrics TCP port parsed from `settings.metrics.bind_address` (only effective when `settings.metrics.enabled = true`).

Notes:

- The module always writes a `[database]` table with `url = "sqlite://${dataDir}/sqlite.db"` unless overridden via `settings.database.url` (you can point it to another path or a PostgreSQL URL for multi-node setups).
- Runtime overrides are possible via `ACME_PROXY_*` environment variables (the module does not set these; configuration file and environment files are the sources of truth).
- The rendered config is exposed at `/etc/acme-proxy/config.toml` and also passed to the service via a systemd credential (`ACME_PROXY_CONFIG=%d/config.toml`).

### Profiles (`services.acme-proxy.profiles.<name>`)

Each profile is exposed by the server at `/profile/<name>` and rendered as `[profiles.<name>]` in TOML. Typed profile options are merged with any free-form values under `settings.profiles.<name>` (typed fields win for keys the module models; other keys such as `[ipam]`/`[notify]` can be supplied via `settings`).

Key profile options:

- `signer.backend` — `"local_ca"` (default), `"relay"`, or `"custom"`.
- `signer.relay.*` — upstream ACME relay settings:
  - `directoryUrl` (required for `relay`)
  - `challengeStrategy` = `"bypass" | "dns01" | "http01"` (default `"bypass"`)
  - `accountKeyPath`, `contact`, `pollIntervalMs`, `pollTimeoutSecs`
  - `eab.kid` / `eab.hmacKey` (both must be set together if configured in Nix; prefer env overrides for secrets)
  - `dns01.*` (RFC 2136 / TSIG, propagation options, optional `challengeAlias`) when `challengeStrategy = "dns01"`
- `signer.localCa.*` — local CA settings (`leafValidityDays`, `certPath`, `keyPath`, `crlPath`).
- `signer.custom.scriptPath` — required for `backend = "custom"`.
- `challenge.enabled` — offered challenge types (`"http-01"`, `"dns-01"`, `"tls-alpn-01"`; default `["http-01"]`).
- `challenge.bypass` — mark challenges valid without network checks (default `false`; use with care).
- `filter.*` — per-profile filter overrides/library entries (`rules`, `default`, `trustedProxies`, `check`, `rule`).
- `eab.enabled` — require EAB for `newAccount` on this profile (credentials managed out-of-band).
- `environmentFiles` — per-profile systemd `EnvironmentFile=` paths (loaded after daemon-wide files).

Important validation/behavior enforced by the module:

- Profile names must match `^[a-z0-9-]+$`.
- `relay` profiles require `directoryUrl`.
- `dns01` relay profiles require RFC 2136 server/zone/TSIG key name; TSIG secret must be provided via option or reachable environment files.
- Relay EAB `kid` and `hmacKey` must be set together when configured in Nix.
- Two profiles must not share signer-owned file paths with differing signer sections (conflicts such as shared relay account key / local CA paths are caught at evaluation time).
- For per-profile secrets, prefer scoped env vars `ACME_PROXY_PROFILES__<NAME>__...` in `environmentFiles` to avoid leaking values across profiles via global `ACME_PROXY_*` overrides.

### Filter (`services.acme-proxy.filter`)

Global policy/filter configuration rendered as top-level `[filter]`:

- `rules` — ordered list of rule names to evaluate (first match wins)
- `default` — fallback decision when no rule matches (`"deny"` by default upstream)
- `trustedProxies` — CIDR/IP ranges whose forwarded header is honored
- `forwardedHeader` — header carrying original client address
- `check.<name>` — named check definitions
- `rule.<name>` — named rule definitions (`when`, `decision = "allow"|"deny"`, optional `message`)

Profiles may override `rules`, `default`, and `trustedProxies`, and can define per-profile `check`/`rule` libraries (merged with global definitions per upstream semantics; the module includes assertions for common invalid/shadowing cases).

Refer to upstream filter documentation for check/rule semantics:
- [Checks](https://acme-proxy.github.io/acme-proxy/filters/checks.html)
- [Policy/rules](https://acme-proxy.github.io/acme-proxy/filters/policy.html)

### systemd service behavior

When enabled, the module defines `systemd.services.acme-proxy` with:

- `DynamicUser=true` and `StateDirectory=acme-proxy`
- `WorkingDirectory = services.acme-proxy.dataDir`
- `ACME_PROXY_CONFIG=%d/config.toml` loaded from a systemd credential
- daemon-wide and per-profile `EnvironmentFile` entries
- restart on failure and restart triggers on rendered config / environment file path changes
- restrictive sandboxing/hardening options (the process handles CA private keys and database state)

### Additional module checks

The module asserts/evaluates several safety and correctness conditions, including:

- at least one profile is declared
- environment file entries are absolute paths
- firewall-open options require parseable bind ports
- `admin`/`metrics` bind addresses must differ from each other and from the server bind address when enabled
- non-loopback admin bind requires `settings.admin.tls.enabled = true`
- filter rule/check references and trusted proxy entries are validated

## Examples

### Minimal local CA profile

```nix
{
  services.acme-proxy = {
    enable = true;

    settings.server = {
      bind_address = "127.0.0.1:3000";
      base_url = "https://ca.example.internal";
    };

    profiles.default = {
      signer.backend = "local_ca";
    };
  };
}
```

### Relay profile with environment-provided secret

```nix
{
  services.acme-proxy = {
    enable = true;

    profiles.letsencrypt = {
      signer.backend = "relay";
      signer.relay = {
        directoryUrl = "https://acme-v02.api.letsencrypt.org/directory";
        contact = [ "mailto:admin@example.com" ];
      };

      # Contains profile-scoped env overrides, e.g.:
      # ACME_PROXY_PROFILES__letsencrypt__SIGNER__RELAY__EAB__HMAC_KEY=...
      environmentFiles = [ "/run/secrets/acme-proxy-letsencrypt.env" ];
    };
  };
}
```
